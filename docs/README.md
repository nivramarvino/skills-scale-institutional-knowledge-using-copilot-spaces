# OctoAcme Project Management Docs

This README is the entry point for OctoAcme's project management practices. Use it to understand the overall approach, navigate the process guides, and quickly find the right guidance whether you are onboarding, starting a new initiative, or actively delivering work.

OctoAcme manages projects through lightweight, repeatable practices that keep teams aligned on customer outcomes, ownership, delivery progress, and learning. The process documentation in this folder is designed to support cross-functional work from initial idea through release and retrospective.

## Core Principles
- **Customer-first**: Prioritize customer value and usability.
- **Iterative delivery**: Deliver small, testable increments.
- **Clear ownership**: Each project has a named Project Manager (PM) and Product Lead.
- **Data-informed decisions**: Measure impact and iterate based on evidence.
- **Psychological safety**: Encourage feedback and learning.

## Getting Started
- **New to OctoAcme?** Start with the [OctoAcme Project Management Overview](./octoacme-project-management-overview.md) to learn the shared principles, roles, lifecycle, and key artifacts.
- **Starting a new project?** Begin with the [Project Initiation Guide](./octoacme-project-initiation.md), then move into [Project Planning](./octoacme-project-planning.md) once the work is approved.
- **In active delivery?** Use [Execution and Tracking](./octoacme-execution-and-tracking.md) for day-to-day team rhythm, [Risk Management and Communication](./octoacme-risks-and-communication.md) for escalations and updates, and [Release and Deployment Guide](./octoacme-release-and-deployment.md) when preparing to launch.

## Project Lifecycle
OctoAcme's project lifecycle is organized into five phases that move work from initial idea to continuous improvement:

1. **Initiation**: Validate the problem, define success metrics, align stakeholders, and confirm the work should move forward.
2. **Planning**: Break the initiative into shippable increments, define acceptance criteria, document risks, and agree on milestones.
3. **Execution**: Deliver the work through regular team rhythms, track progress against milestones, and escalate blockers early.
4. **Release**: Prepare the release, complete deployment checks, verify production readiness, and communicate the launch.
5. **Close & Retrospective**: Review outcomes, capture lessons learned, and turn improvements into owned follow-up actions.
